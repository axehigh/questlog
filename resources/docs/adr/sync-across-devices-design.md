# Simple Cross-Device Sync Design for Chore Quest

## Goal
Allow a parent on another device (or phone/tablet) to view and approve chores, check balances, and review pending submissions without a heavy backend or complex authentication.

## Proposed Approaches (Simple & Lightweight)

### 1. Peer-to-Peer / Local Network WebSocket / BroadcastChannel (If on same Wi-Fi)
- **How it works:** Run a lightweight Node.js helper script or WebSocket server on one local machine/device (e.g., laptop running Python/Node), or use WebRTC data channels for direct device-to-device connection.
- **Pros:** No external server needed.
- **Cons:** Requires devices to be on the same local network and a companion background script.

### 2. Zero-Config Cloud JSON Bin / KV Store (JSONBlob, JSONBin.io, KV/Workers, or Pastebin-like API)
- **How it works:**
  - Assign a unique shared "Family Sync ID" (or PIN / Session URL token) stored in localStorage.
  - Whenever state changes (chore completed, parent approval), the app pushes an encrypted/plain JSON payload to a free public JSON storage endpoint (e.g., `jsonblob.com`, `kv.io`, or a lightweight serverless Worker).
  - The other device polls every few seconds or listens for updates (polling / SSE / WebSockets) and merges state.
- **Pros:** Works anywhere across mobile/desktop over cellular or different networks. Extremely easy to implement with standard `fetch()`.
- **Cons:** Public or unauthenticated endpoints could technically be guessed if the ID is simple (though security is explicitly not a priority here).

### 3. QR Code / Export-Import State Sync (Ultra Simple / No Backend)
- **How it works:** Parent device scans a QR code generated by the child's device (or vice versa) containing the full JSON state or sync diff, or shares a one-time sync link.
- **Pros:** 100% serverless, zero infrastructure.
- **Cons:** Manual or periodic rather than real-time push.

---

## Recommended Implementation for Chore Quest: **JSONBlob / REST Key-Value Sync**

Given that Chore Quest is a static single-page app with no build step:
1. **Sync Settings in Parent Admin:** Add a **"Cloud Sync"** section where parents can enter a shared Sync ID (or auto-generate one).
2. **Push on Change:** Debounce `saveToStorage()` and push the state object to a free cloud JSON store (like JSONBlob API or custom Worker).
3. **Poll / Refresh:** Poll every 10 seconds or on window focus for updates, comparing timestamps or version numbers to merge safely.
